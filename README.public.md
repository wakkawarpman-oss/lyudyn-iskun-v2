# 🛰️ OKINT-PRO (C4ISR Platform) — Public Architecture & Engineering Guide

> **Security Level:** `security_level: public`  
> **Status:** Open-Source Architecture Specification (Revision V3.6-Public)  
> **Scope:** Geospatial data fusion, multi-INT OSINT pipelines, kinematic tracking, and reproducible static analysis for civil defense and tactical awareness.

---

## 📌 1. Загальний огляд системи (Executive Summary)

**OKINT-PRO** — відкрита архітектурна платформа раннього сповіщення про повітряні загрози, кінематичного моделювання руху об'єктів та оцінки ризиків для цивільної та критичної інфраструктури.

Система поєднує методи просторово-часового моделювання (GIS), обробку природної мови (NLP) для публічних моніторингових каналів, ймовірнісний статистичний аналіз (Bayesian Inference) та геофізичну корекцію траєкторій (Digital Elevation Models & Atmospheric Vectors).

### Ключові архітектурні контури (3-Tier Segmentation)

Для забезпечення інформаційної безпеки, захисту від ворожого оцінювання результатів ударів (Battle Damage Assessment — BDA) та наукової відтворюваності, система строго поділена на три ізольованих контури:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              OKINT-PRO 3-TIER ARCHITECTURE                             │
└────────────────────────────────────────────────────────────────────────────────────────┘

 [ РІВЕНЬ 1: PUBLIC (OSINT) ] • security_level: public
 ├── Агреговані публічні дані, укриття (OpenStreetMap), офіційні тривоги (alerts.in.ua)
 ├── Огрублені координати (Anti-BDA: розмиття до районного центру ~2–5 км)
 └── Доступ: Відкритий WebGIS / базова роль (guest, analyst_public)

                           ▲
                           │  [ Data Scrubber & Sanitization Gateway ]
                           │
 [ РІВЕНЬ 2: RESEARCH / SIMULATION ] • security_level: research
 ├── Синтетичні сценарії, датасети перевірки, симуляції розльоту уламків
 ├── Офлайн-архів DuckDB + GeoParquet, валідація дрейфу моделей (Evidently, Great Expectations)
 └── Доступ: analyst_research (ізольовано від бойових мереж)

                           ▲
                           │  [ Policy Enforcement Point (PEP) + Access Approvals ]
                           │
 [ РІВЕНЬ 3: RESTRICTED OPERATIONAL ] • security_level: restricted
 ├── Точні координати сенсорів, прямі радарні фіди, суворі часові мітки
 ├── Експорт Cursor-on-Target (CoT XML 2.0 / MIL-STD-2525) для авторизованих терміналів
 └── Доступ: operator / admin ТІЛЬКИ ПРИ НАЯВНОСТІ АКТИВНОГО СХВАЛЕННЯ (Approval TTL 4–24h)
```

## 🗺️ 2. Геопросторовий стек та фізичне моделювання

### 2.1 Цифрові моделі рельєфу (DEM) та радіовидимість (Viewshed)

Замість спрощених геометричних кіл або фіксованих формул радіогоризонту, архітектура спирається на стандартизовані відкриті просторові дані:

* **Copernicus DEM GLO-30** (30-метрова цифрова модель поверхні) як базовий шар рельєфу.
* **SRTM / NASADEM** як резервні шари висот.
* **GDAL / Rasterio / rioxarray** — обрізка, репроекція (WGS-84 ➔ UTM / ENU) та тайлінг растрових даних.
* **WhiteboxTools / GRASS GIS** — розрахунок зон прямої видимості (Viewshed Analysis) для різних висот сенсора над рівнем ґрунту (AGL: 5м, 15м, 30м).
* **Урахування фізичних факторів**:
  - Ефективна кривизна Землі з коефіцієнтом нормальної атмосферної рефракції ($k = 4/3$);
  - Формування окремих растрових масок: `terrain_obstruction` (затінення рельєфом) та `terrain_uncertainty` (похибка DEM у пересіченій місцевості).
  - **Правило верифікації**: географічне затінення трактується не як факт маскування, а як область зниження ймовірності виявлення сенсором.

### 2.2 Геодезичні стандарти та представлення даних

* **PROJ / pyproj** та **GeographicLib** — прецизійний розрахунок відстаней та азимутів на еліпсоїді WGS-84 (Vincenty/Karney geodesics).
* **H3 / S2 Geometry** — гексагональна просторова індексація для стабільної агрегації подій без деанонімізації конкретних будівель.
* **GeoJSON, GeoParquet, FlatGeobuf** — стандартизовані оптимізовані формати передачі просторових даних.
* **PMTiles / MBTiles** — автономне офлайн-поширення тайлів без звернення до зовнішніх картографічних серверів.

## 📡 3. OSINT, моніторинг повідомлень та перевірка медіа

### 3.1 Обережний моніторинг текстового потоку

* **Telethon / Pyrogram** — збір інформації виключно з відкритих публічних каналів моніторингу з дотриманням rate limits.
* **RSS / Atom & GDELT** — інтеграція офіційних відомчих зведень та міжнародних моніторингових баз.
* **Захист приватності (PII Protection)**: інтеграція фільтрації персональних даних (Microsoft Presidio або регулярні евристики) до збереження тексту в БД.
* **NLP & Топоніміка**:
  - **spaCy / Stanza** — Named Entity Recognition (NER) для вилучення географічних сутностей;
  - **RapidFuzz** — нечітке порівняння та нормалізація історичних/змінених назв населених пунктів;
  - Двоетапний пре-фільтр `is_tactical_threat_candidate()` для автоматичного відкидання цивільного, побутового та судового шуму.

### 3.2 Верифікація фото та відео (Анти-ІПСО та медіа-аудит)

* **pHash & dHash (Perceptual Hashing)** — генерація 64-бітних відбитків зображень для виявлення повторного використання архівних матеріалів.
* **ExifTool** — вилучення метаданих (із застереженням: наявність EXIF не є гарантією автентичності, оскільки легко підробляється).
* **FFmpeg / ffprobe** — аналіз контейнерів, перевірка артефактів монтажу, цілісності відеопотоку та часових міток.
* **InVID-WeVerify & Reverse Image Search** — інтеграція у робоче місце аналітика для ручної перевірки ключових кадрів.

## 🎙️ 4. Акустичний та RF/SDR дослідницький контур

### 4.1 Акустична обробка ознак (Feature-Only Storage)

Для запобігання перевантаженню сховищ та захисту конфіденційності сирий звук не зберігається. Зберігаються виключно векторні ознаки:

* **librosa / SciPy Signal / Torchaudio** — розрахунок спектрограм, Mel-Frequency Cepstral Coefficients (MFCC), spectral centroid, spectral flux.
* **OpenSoundscape / YAMNet** — класифікація сигналів двигунів внутрішнього згоряння.
* **Наукове застереження**: спектральний пік у діапазоні 80–250 Гц притаманний широкому класу цивільних двигунів (генератори, мотоцикли, газонокосарки). Ідентифікація загрози дозволяється виключно при просторово-часовій крос-валідації щонайменше 2–3 незалежними станціями з оцінкою різниці часу прибуття сигналу (TDoA).

### 4.2 Моніторинг радіочастотного середовища (SigMF Standard)

* **SoapySDR & GNU Radio** — взаємодія з SDR-приймачами через відкриті абстракції.
* **SigMF (Signal Metadata Format)** — міжнародний відкритий формат збереження метаданих радіоперехоплень (частота, смуга, sample rate, координати приймача, тип поляризації).
* **Застереження від хибних висновків**: наявність активності в діапазонах 1.4 ГГц або 5.8 ГГц не маркується автоматично як сигнал БпЛА (діапазони насичені цивільним Wi-Fi, FPV-відеопередавачами, промисловими телеметричними лінками).
* **Публічна політика**: будь-які точні частоти, азимути та розташування приймачів підлягають безумовному приховуванню (redaction) у публічних звітах.

## 🌦️ 5. Ансамблева метеорологія та кінематика Калмана

### 5.1 Ансамбль метеорологічних джерел

Замість залежності від одного постачальника впроваджено багатомодельний ансамбль:
* **Open-Meteo REST API** (оперативна сітка);
* **NOAA GFS & ECMWF Open Data** (глобальні синоптичні прогнози);
* **METAR / TAF** (локальні фактичні спостереження метеостанцій).

Оцінюються параметри вітру на ешелонах 100м, 300м, 500м, 750м (рівень ~925 hPa): швидкість, напрямок, пориви, турбулентність.

### 5.2 Фізична модель руху та оцінка похибок

Модель відкидає «одноточкові» прогнози ETA і розділяє кінематику на складові:
$$\vec{V}_{\text{ground}} = \vec{V}_{\text{air}} + \vec{V}_{\text{wind}}$$
* **FilterPy / Stone Soup** — фільтр Калмана (Constant Velocity / Constant Acceleration у декартовій площині ENU).
* **Еліпс коваріації $P_{k|k}$** розгортається у **конус невизначеності** маневру з довірчими інтервалами ($1\sigma, 2\sigma, 3\sigma$).
* Значення очікуваного часу прибуття подається виключно як інтервал (наприклад, `ETA: 14:22 [14:18 – 14:27]`, confidence 85%).

## 🗄️ 6. Архітектура даних: Подієва модель та Data Lake

Для запобігання ситуаціям, коли непідтверджений слух або сирий пік сенсора одразу стає «ціллю на мапі», впроваджено строгу ієрархію сутностей:

```
[Observation / Сирий замір] ➔ [Report / Повідомлення] ➔ [Track / Траєкторія]
             ➔ [Event / Кластеризована подія] ➔ [Assessment / Аналітичний висновок]
             ➔ [Decision / Дія оператора] ➔ [Audit Record / Незмінний журнал]
```

### Стек збереження та обробки:
* **PostgreSQL 15 + PostGIS** — реляційне геопросторове ядро оперативної карти.
* **DuckDB + Apache Parquet** — колоночний аналітичний архів для відтворюваного post-event аналізу та ретроспективних звітів.
* **NATS JetStream / Redis** — брокери повідомлень з гарантією доставки та семантичним кешуванням.
* **dbt & Great Expectations** — декларативне тестування трансформацій даних та контроль якості вхідних потоків.

## 🧪 7. Перевірка якості, калібрування та ML Governance

* **Evidently AI & Pandera** — моніторинг дрейфу даних (Data Drift) та калібрування ймовірностей.
* **DVC (Data Version Control) & MLflow** — повна відтворюваність датасетів, версій моделей та результатів тестів.
* **Відмова від непідтверджених метрик**: заяви на кшталт «FPR < 0.48%» замінено на прозорі звіти валідації на контрольних датасетах із публікацією Precision-Recall кривих, матриць помилок (Confusion Matrix) та Brier Score для калібрування довіри.

## 🔒 8. Безпека платформи (Security Hardening)

* **Ізоляція мереж**: адміністрування та доступ до операційного контуру здійснюється виключно через **Tailscale / WireGuard** або **Cloudflare Zero Trust** без відкриття портів назовні.
* **Управління секретами**: вилучення всіх відкритих ключів з конфігурацій, перехід на **SOPS + age** або HashiCorp Vault.
* **Аудит експорту**: заборона доступу до військових CoT-потоків без взаємної автентифікації mTLS та наявності запису в журналі доступу.
* **Статичний аналіз коду в CI/CD**: автоматичні перевірки через `Trivy` (контейнери), `Semgrep` (безпека коду) та `Gitleaks` (запобігання витоку токенів).
