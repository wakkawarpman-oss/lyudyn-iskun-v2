# 📋 ACCESS CONTROL RUNBOOK: Регламент Доступу C4ISR OKINT-PRO

## 1. Офіцер Безпеки (Security Officer)
- Посадова особа: **Security Officer** (Синтетичний ідентифікатор: `SECURITY_OFFICER_1`, реальні облікові дані завантажуються виключно з безпечного сховища Vault / змінних середовища).
- Виключне право затвердження заявок на доступ до контуру **Restricted Operational**.
- Канал зв’язку: Прямий інтерфейс Telegram-бота (інлайн-кнопки схвалення) або безпечний API Gateway.

## 2. Життєвий Цикл Заявки на Доступ (Request Lifecycle)
1. **Подання заявки (`POST /api/v1/access/request`)**:
   - Оператор вказує сектор (`geo_scope`), ресурс (`tactical_events`, `cot_stream`) та оперативне обґрунтування.
   - Заявка отримує унікальний ідентифікатор `req_<hash>` та статус `PENDING`.
2. **Сповіщення Офіцера Безпеки**:
   - Бот надсилає картку інциденту Офіцеру Безпеки з кнопками:
     - `[✅ СХВАЛИТИ (24 год)]` -> `appr_perm:<req_id>:<sector>`
     - `[❌ ВІДХИЛИТИ]` -> `rejc_perm:<req_id>:<sector>`
3. **Активація Доступу**:
   - При натисканні «СХВАЛИТИ» у Redis створюється ключ `tactical:approval:<req_id>:<sector>` з TTL = **86400 секунд (24 години)**.
   - Запис дублюється у таблицю `restricted_ops.access_approvals`.
   - Незмінний аудит-запис фіксується у `audit_sec.security_audit_trail`.
4. **Автоматичне Спливання (Expiration)**:
   - Після 24 годин ключ у Redis автоматично видаляється.
   - Запити оператора повертаються у безпечний цивільний контур без сповільнення або збою системи.

## 3. Аварійний Режим (Break Glass Procedure)
- У разі надзвичайної бойової обстановки та тимчасової недоступності Офіцера Безпеки застосовується аварійний ключ доступу:
  - Ендпоінт: `POST /api/v1/access/break-glass`
  - Авторизація: `BREAK_GLASS_TOKEN` (зберігається у фізичному сейфі чергового або розділений за схемою Шаміра)
  - Термін дії аварійного доступу: **максимум 4 години**
  - Аудит: подія фіксується зі статусом `BREAK_GLASS_TRIGGERED` та найвищим пріоритетом аудиту.
