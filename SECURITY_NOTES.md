# 🛡️ ПРАВИЛА БЕЗПЕКИ ТА OPSEC РЕГЛАМЕНТ (SECURITY_NOTES.md)

> **Призначення:** Обов'язкова інструкція з операційної безпеки (OPSEC), захисту чутливих даних та публікації вихідного коду платформи OKINT-PRO C4ISR.  
> **Security Clearance:** `security_level: public`  
> **Аудиторія:** Розробники, DevOps інженери, аналітики даних, оператори чергових змін.

---

## 📌 1. Фундаментальний принцип: «Відкрите джерело» ≠ «Безпечно публікувати»

Багато компонентів системи за своєю природою базуються на відкритій інформації (OSINT). Проте критично важливо розуміти межу, за якою відкриті дані перетворюються на загрозу безпеці:

### Чотири вектори підвищення ризику:
1. **Агрегація (Aggregation Risk)**:  
   Коли з десятків розрізнених відкритих фактів (пости очевидців, супутникові знімки, погода) синтезується єдина цілісна бойова картина в реальному часі. У поєднанні це стає стратегічною розвідінформацією.
2. **Деталізація (Detailing Risk)**:  
   Публікація точних координат географічних точок (мікрофонів, польових SDR, камер спостереження, енергетичних вузлів, позицій ППО).
3. **Прив'язка до реального часу (Temporal Relevance)**:  
   Трансляція інформації «прямо зараз», «у цю хвилину», «під час поточної хвилі нальоту». Це перетворює аналітику на пряму підказку ворогу.
4. **Контекст дій (Actionable Guidance)**:  
   Формулювання конкретних тактичних директив («на яких частотах працювати», «де саме є мертва зона радіолокації»).

## 🚫 2. Категоричні заборони для публічних репозиторіїв та звітів

У будь-яких файлах, які потрапляють до Git, відкритих звітів чи публічної документації, **СУВОРО ЗАБОРОНЕНО** розміщувати:

* ❌ **Реальні IP-адреси** бойових серверів, хостів GCP, баз даних або внутрішніх контейнерів.
* ❌ **Дійсні API-ключі та токени**: xAI Grok, Groq LPU, Telegram Bot Token, Telegram App API ID/Hash, Fernet Secret Keys.
* ❌ **Точні координати сенсорів або об'єктів**: розташування радарних постів, мікрофонних станцій чи польових приймачів.
* ❌ **Сирі вивантаження Cursor-on-Target (CoT XML)**, які транслюються в бойові термінали (ATAK, Kropyva).
* ❌ **Тактичні інструкції з протидії РЕБ** або конкретні уразливі діапазони радіозв'язку.

## 🛡️ 3. Політика редагування та використання синтетичних значень (Redaction Policy)

Усі приклади, тести, конфігурації та навчальні посібники повинні використовувати **виключно синтетичні значення**:

| Тип даних | Заборонено (Бойовий зразок) | Дозволено (Синтетичний приклад) |
|---|---|---|
| **IP-адреси** | `136.113.156.17` | `192.0.2.10` або `203.0.113.50` (RFC 5737 TEST-NET) |
| **Домени** | Внутрішні хости / бойові сервери | `example.com`, `tactical-sim.internal` |
| **Ключі API** | Дійсні токени `xai-...`, `gsk_...` | `xai-SYNTHETIC_XAI_KEY_REDACTED_PLACEHOLDER` |
| **Координати** | Точні WGS-84 (наприклад, `50.45014, 30.52341`) | Огрублені (наприклад, `50.45, 30.52`, похибка >2 км) |
| **Ідентифікатори сенсорів** | Реальні позивні мікрофонів/постів | `SENSOR_ID_SYNTHETIC_001` |
| **Ідентифікатори цілей** | Бойові треки | `DRONE-SIM-001`, `TARGET-SYNTHETIC-ALPHA` |

## 🔄 4. Регламент ротації секретів (Secret Rotation Runbook)

Якщо будь-який бойовий секрет випадково потрапив до звіту, логу чи Git-коміту:

1. **Негайне анулювання (Revocation)**:  
   Ключ має бути негайно відкликаний в панелі провайдера (xAI Console, Groq Console, Telegram `my.telegram.org`). Сам факт видалення рядка з Git **не є безпечним**, оскільки ключ залишається в історії репозиторію.
2. **Очищення історії Git**:  
   Використання утиліти `git-filter-repo` або `BFG Repo-Cleaner` для повного видалення сліду компрометованого файлу з усіх гілок та тегів.
3. **Генерація нових ключів**:  
   Нові ключі генеруються через захищені генератори (наприклад, `openssl rand -hex 32` для Fernet/JWT) і вносяться безпосередньо у захищене сховище або зашифрований SOPS файл.
4. **Перезапуск контейнерів**:  
   Перезапуск сервісів для підтягування оновлених змінних середовища.

## 🎯 5. Запобігання ворожому коригуванню вогню (Anti-BDA Protection)

У публічному контурі (`security_level: public`) діє обов'язковий протокол захисту:

* **Координатне розмиття**: публічний шар карти та API (`/api/events`) заокруглює координати до 2 знаків після коми (радіус невизначеності ~1.5–2.5 км).
* **Часова затримка (Time Delay)**: публікація інформації про прильоти або роботу ППО дозволяється виключно після офіційного підтвердження органів влади (Повітряні Сили ЗСУ, ОВА) або з фіксованою затримкою (не менше 30–60 хвилин).
* **Заборона фотофіксації прильотів**: pHash-дедуплікатор блокує свіжі фото до верифікації офіційними джерелами.

## ⚖️ 6. Контроль доступу та незмінний аудит (WORM Audit)

* **Approvals Workflow**: доступ оператора до оперативного контуру (`restricted_ops`) відкривається лише після подання обґрунтованої заявки та її підтвердження офіцером безпеки на фіксований час (4–24 години).
* **Незмінний журнал**: будь-який запит до точних радарних треків чи експорту CoT фіксується у таблиці `audit_sec.security_audit_trail` (правила БД `no_update_audit` та `no_delete_audit` блокують будь-які спроби модифікації або видалення записів).
