# 🛡️ SECURITY ARCHITECTURE: Триконтурна Модель OKINT-PRO

## 1. Концепція Зон Довіри (Trust Zones)

Система C4ISR OKINT-PRO сегментована на три фізично та логічно ізольовані контури безпеки:

```
+-------------------------------------------------------------------------+
|                           ПУБЛІЧНИЙ ІНТЕРНЕТ                            |
+-------------------------------------------------------------------------+
                                    |
                                    v [Cloudflare Tunnel / WAF]
+-------------------------------------------------------------------------+
| 🌐 PUBLIC OSINT КОНТУР                                                   |
| - Ролі: guest, analyst_public                                           |
| - Схвалення адміна: НЕ ВИМАГАЄТЬСЯ                                      |
| - Дані: 100% WGS-84 кінематика, санітизовані події, укриття, тривоги   |
| - Захист: Нульовий витік об’єктів ВПК, підстанцій, РЕБ-частот та пусків |
+-------------------------------------------------------------------------+
                                    |
                                    v [API Gateway / AuthZ Middleware]
+-------------------------------------------------------------------------+
| 🔬 RESEARCH / SIMULATION КОНТУР                                         |
| - Ролі: analyst_research                                                |
| - Схвалення адміна: РОЛЬ ВИДАЄТЬСЯ РАЗОВО (без щоденних схвалень)       |
| - Дані: Синтетичні симуляції, історичний архів (>90 днів), ML-датасети   |
+-------------------------------------------------------------------------+
                                    |
                                    v [Policy Engine + Security Officer 24h Approval]
+-------------------------------------------------------------------------+
| ⚔️ RESTRICTED OPERATIONAL КОНТУР                                        |
| - Ролі: operator, admin, security_officer                               |
| - Схвалення адміна: СУВОРО ОБОВ’ЯЗКОВЕ (Security Officer @btntrx, 24h)  |
| - Дані: Cursor-on-Target (CoT XML), конуси загроз підстанціям, РЕБ,    |
|   радіорозвідка SIGINT, тріангуляція стартових майданчиків             |
+-------------------------------------------------------------------------+
```

## 3. Незмінний Аудит Безпеки (WORM - Write Once, Read Many)

Усі спроби звернення до чутливих ресурсів фіксуються в таблиці `audit_sec.security_audit_trail`. Правила PostgreSQL `no_update_audit` та `no_delete_audit` блокують будь-яку модифікацію або видалення записів навіть суперкористувачем.
